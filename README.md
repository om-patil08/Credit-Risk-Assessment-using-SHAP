# Credit Ledger — Loan Risk Assessment

**A machine-learning web app that estimates the probability that a loan applicant will default, and flags the application as High Risk or Low Risk.**

Built with scikit-learn, XGBoost, FastAPI, and a vanilla HTML/CSS/JS frontend styled as an "underwriting desk".

## Overview

This is an end-to-end binary classification project:

1. **Notebook** – EDA, data validation, model comparison, hyperparameter tuning, probability calibration, threshold selection, and SHAP explainability.
2. **API** – a FastAPI service loads the saved model and decision threshold at startup and exposes `/predict`.
3. **Web app** – a single-page form where the user enters an application and gets a default probability gauge and a "HIGH RISK / LOW RISK" stamp.

The target is `loan_status` (`1` = default, `0` = no default). The classes are imbalanced (about 78% non-default vs 22% default), so the project uses class weighting, stratified splits/CV, precision/recall-based metrics, and a tuned decision threshold instead of the default 0.5.

## Features

- Predicts **default probability** plus a High/Low Risk verdict using a tuned threshold
- Compares **Logistic Regression** (baseline) with **XGBoost**
- Handles class imbalance (`class_weight="balanced"`, `scale_pos_weight`)
- **Probability calibration** (`CalibratedClassifierCV`, sigmoid) so outputs behave like real probabilities
- **SHAP** global and local explanations in the notebook
- False-positive / false-negative analysis
- Auto-calculated **loan-to-income ratio** in the form (editable)
- Live **service status** indicator in the header (checks `/openapi.json`)
- Animated circular gauge with a threshold tick mark, and a "stamp" verdict animation
- Responsive layout and `prefers-reduced-motion` support

## Dataset

**File:** `credit_risk_dataset.csv` (not included in the repo; place it next to the notebook)

- ~32,500 raw rows, 12 columns
- **Target:** `loan_status` (0 = non-default, 1 = default)

| Group              | Features                                                                                         |
| ------------------ | ------------------------------------------------------------------------------------------------ |
| Applicant          | `person_age`, `person_income`, `person_home_ownership`, `person_emp_length`                      |
| Loan               | `loan_intent`, `loan_grade`, `loan_amnt`, `loan_int_rate`, `loan_percent_income`                 |
| Credit bureau file | `cb_person_default_on_file`, `cb_person_cred_hist_length`                                        |

## Machine Learning Pipeline

### Data validation & cleaning
- Removed duplicate rows
- Kept ages between 18 and 100 (a handful of ages above 100 were removed)
- Removed employment lengths greater than the person's age or above 60 years
- Removed rows with a non-positive loan amount

### Splitting
- 80/20 **stratified** train/test split (`random_state=42`) to keep the class ratio equal in both sets

### Preprocessing (`ColumnTransformer`)
- **Numeric:** median imputation → `StandardScaler`
- **Categorical:** constant imputation (`"Missing"`) → `OneHotEncoder(handle_unknown="ignore")`

### Models
1. **Logistic Regression** – `class_weight="balanced"`
2. **XGBoost** – `scale_pos_weight = negatives / positives` (≈ 19,772 / 5,445 in the training set)

Both were compared with 5-fold stratified cross-validation (ROC-AUC, accuracy, precision, recall, F1).

### Tuning, calibration and threshold
- `RandomizedSearchCV` on XGBoost: 150 iterations, 5-fold CV, scored on **average precision** (best CV score ≈ 0.90). Parameters searched: `n_estimators`, `max_depth`, `learning_rate`, `subsample`, `colsample_bytree`, `min_child_weight`, `gamma`
- **Sigmoid calibration** with `CalibratedClassifierCV`
- **Decision threshold** chosen by maximizing F1 along the precision–recall curve of the calibrated probabilities, then saved to `best_threshold.pkl`

### Explainability
- SHAP `TreeExplainer` with a summary plot (global) and a waterfall plot (single applicant)

## Model Results

5-fold stratified cross-validation on the training set (mean across folds):

| Model               | ROC-AUC | Accuracy | Precision | Recall | F1    |
| ------------------- | ------- | -------- | --------- | ------ | ----- |
| Logistic Regression | 0.870   | 0.811    | 0.543     | 0.777  | 0.639 |
| XGBoost             | 0.939   | 0.908    | 0.789     | 0.785  | 0.787 |

XGBoost beats the logistic baseline on every metric, most clearly on precision (fewer safe applicants wrongly flagged).

## Getting Started

### Prerequisites
- Python 3.9+ (Render config uses 3.12)

### 1. Clone

```bash
git clone https://github.com/<your-username>/<your-repo>.git
cd <your-repo>
```

### 2. Install dependencies

Create a `requirements.txt`:

```
fastapi
uvicorn
pandas
numpy
scikit-learn
xgboost
joblib
```

(Add `matplotlib`, `seaborn`, `shap`, `scipy`, and `jupyter` if you want to re-run the notebook.)

```bash
pip install -r requirements.txt
```

> Use the same scikit-learn and XGBoost versions for training and serving, or loading the `.pkl` files may fail.

### 3. (Optional) Retrain

Run `credit_risk_model.ipynb` top to bottom. The last cells write `credit_risk_model.pkl` and `best_threshold.pkl`. Keep both in the same folder as `main.py`.

### 4. Run

```bash
uvicorn main:app --reload --port 8000
```

- App: http://localhost:8000
- Swagger docs: http://localhost:8000/docs

The frontend calls `/predict` and `/openapi.json` with relative URLs, so no API URL needs to be configured when served by FastAPI.

## API Reference

### `POST /predict`

**Request**

```json
{
  "person_age": 30,
  "person_income": 600000,
  "person_home_ownership": "RENT",
  "person_emp_length": 5,
  "loan_intent": "PERSONAL",
  "loan_grade": "B",
  "loan_amnt": 100000,
  "loan_int_rate": 11.5,
  "loan_percent_income": 0.17,
  "cb_person_default_on_file": "N",
  "cb_person_cred_hist_length": 6
}
```

**Response**

```json
{
  "default_probability": 0.12,
  "default_prediction": 0,
  "threshold": 0.55,
  "Result": "Low Risk"
}
```

(Values above are illustrative.)

**Accepted categorical values**

| Field                       | Values                                                                      |
| --------------------------- | --------------------------------------------------------------------------- |
| `person_home_ownership`     | `RENT`, `MORTGAGE`, `OWN`, `OTHER`                                          |
| `loan_intent`               | `PERSONAL`, `EDUCATION`, `MEDICAL`, `VENTURE`, `HOMEIMPROVEMENT`, `DEBTCONSOLIDATION` |
| `loan_grade`                | `A` – `G`                                                                   |
| `cb_person_default_on_file` | `Y`, `N`                                                                    |

**How the decision is made:** `default_prediction = 1` when `default_probability >= threshold`.

```bash
curl -X POST http://localhost:8000/predict \
  -H "Content-Type: application/json" \
  -d '{"person_age":30,"person_income":600000,"person_home_ownership":"RENT","person_emp_length":5,"loan_intent":"PERSONAL","loan_grade":"B","loan_amnt":100000,"loan_int_rate":11.5,"loan_percent_income":0.17,"cb_person_default_on_file":"N","cb_person_cred_hist_length":6}'
```

## Frontend

A three-section "ledger" form (Applicant, Loan request, Credit bureau file) followed by a verdict panel containing:

- a circular **gauge** showing default probability, with a tick marking the decision threshold
- an animated **stamp** (HIGH RISK in red / LOW RISK in green)
- a small facts table: default probability, decision threshold, model verdict

`loan_percent_income` is calculated automatically from income and loan amount, but you can override it.

## Deployment (Render)

`render.yaml` defines a free-tier Python web service:

```yaml
services:
  - type: web
    name: credit-ledger
    runtime: python
    plan: free
    buildCommand: pip install -r requirements.txt
    startCommand: uvicorn main:app --host 0.0.0.0 --port $PORT
    envVars:
      - key: PYTHON_VERSION
        value: 3.12.11
    autoDeploy: true
```

Steps:
1. Commit `credit_risk_model.pkl`, `best_threshold.pkl`, `requirements.txt`, `main.py`, and the `Static/` folder
2. On Render, create a **Blueprint** (or Web Service) from the repo
3. Render builds and starts the app automatically on each push

On the free tier the service sleeps when idle, so the first request can be slow.

## Limitations

- Trained on a single public dataset; may not reflect real lending populations
- The UI uses ₹ for currency, but the dataset's original currency is not specified, so treat amounts as illustrative
- Calibration and threshold are tuned on one test split
- A credit model used for real decisions would need fairness, compliance, and monitoring work
